# Application architecture

## Organization

The code is organized by feature. `core/` holds what does not belong to any feature and never imports from `features/`; each feature has the `domain`, `data`, `stores` and `presentation` layers when it needs them. Business rules live in MobX stores, separate from the interface and from disk access.

```text
lib/
  main.dart                initializes dependencies, discovers languages and starts the app
  app/                     PlotcraftApp: MaterialApp, localization, the active theme, the stage and the paper grain
  core/
    platform/              WindowService (window size) and the native spell checker
    storage/               LocalStorage (preferences with SharedPreferences)
    icons/                 IconRef and IconCatalog (generated catalog of icons_flutter icons)
    theme/                 ThemeDefinition, interface fonts, PlotcraftTokens (stages, radii, motion) and StageScope
    ui/                    reusable components (buttons, chips, fields, dialogs, menus, images)
    ui/gris/               the watercolour look: wash, grain, rings, arches, strokes, reveals (see visual-language.md)
  features/
    projects/              project library
    project_creation/      project creation
    project_workspace/     workspace of an open project
    preferences/           theme, font, language and projects folder
```

- **`features/projects/`**
  - `domain/` has `StoryProject`, `ProjectMetadataInput` (data and validation for title, tags and the other fields, used when creating and editing) and `CoverImageRules` (cover extensions and size).
  - `data/` has `ProjectRepository` (folders, path index and migration) and `ProjectCreationService` (initial structure on disk).
  - `stores/` has `ProjectStore`.
  - `presentation/` has the home screen, the sidebar, the header, the cards and the cover palettes.
- **`features/project_creation/`**: `ProjectCreationStore` and the creation page.
- **`features/project_workspace/`**
  - `domain/` has the book (Deltas), the narrative elements, the Delta↔Markdown conversion, the mention index and the occurrence search.
  - `data/` has one repository per subject, all on top of `ProjectFiles` (manifest and atomic writes): `BookRepository`, `NarrativeRepository`, `GalleryRepository` and `ProjectMetadataRepository`. `ProjectWorkspaceRepository` groups them and loads everything at once.
  - `stores/` has `ProjectWorkspaceStore`: the open project, the manuscript, the gallery, the metadata and the operation states.
  - `stores/` also has `WorkspaceController` (MobX): open tabs, side panel, inspector, panel sizes, chapter text buffers and autosave. It does not open dialogs; `WorkspaceActions` is what asks the user.
  - `domain/` also has the element types (`element_type.dart`, `element_type_catalog.dart`), the images, relations, phase anchors and the migration of old elements.
  - `presentation/` is divided into `shell/` (activity bar, side panel, tab area and `WorkspaceShell`, which joins everything with draggable dividers), `manuscript/` (editor, toolbar, preview and chapter list), `reading/` (reading mode), `elements/` (list with search and filters, type picker, type editor, element editor split into panels for images, relations, details, sections and phases, and the appearance, phase and gallery dialogs) and `widgets/` (overview, gallery, metadata and inspector). `workspace_actions.dart` gathers the operations started by the person (closing a tab, chapters, gallery, metadata, full screen).
- **`features/preferences/`**: `ThemeStore` (theme catalog, font and persistence) and the preferences page.
- **`core/ui/`**: components receive data and callbacks; colors, focus, borders and states come from the active theme. `ProjectImage` shows images from the project folder and `ProportionalImage` shows them whole, in their own shape.
- The interface uses Feather icons from the `icons_flutter` package; the default typography is Times New Roman, with selectable bundled families.
- `assets/translations/`, `assets/themes/` and `assets/fonts/` hold the languages, the JSON themes and the fonts (declared in `pubspec.yaml`). `shaders/` holds the two fragment shaders of the watercolour wash and the paper grain.

Dependencies between features always point toward `projects` (domain and data); only the home screen of `projects` composes the pages of the other features.

The icon catalog (`lib/core/icons/icon_catalog.g.dart`) is generated by `dart tool/gen_icon_catalog.dart`: the `icons_flutter` package has no name → icon registry, so the script reads the constants of seven sets and generates references to them, which keeps tree-shaking working. Only the icon's set and name are saved in projects.

The stores' `.g.dart` files are generated by `mobx_codegen`; edit the stores' source files, not the generated ones.

Presentation components receive data and callbacks. Domain logic stays in the stores, so widgets do not persist anything directly.

## Packages

What does not depend on Flutter lives in `packages/plotcraft_core` (pure Dart): `StoryProject`, the book and element models, the Delta↔Markdown converters, Delta editing without an editor (`DeltaEdit`), the repositories, `ProjectLibrary`, `StoryWorkspace` and the protocol of the bridge with the app. Paths inside the package mirror those in `lib/` (`features/...`). The app imports `package:plotcraft_core/...`; whatever draws, stores preferences or talks to the system (MobX stores, widgets, `ProjectRepository`, `QuillController`) stays in `lib/`. `packages/plotcraft_mcp` is the MCP server (see [MCP](mcp.md)).

Model colors are ARGB numbers (`colorValue`) and icons are `IconRef {set, name}`; the app reads them as `Color` and `IconData` through extensions (`element_colors.dart`, `icon_data.dart`).

## Sample project

The app ships a complete story, "Herdeiros do Silêncio", in `assets/sample/herdeiros-do-silencio/` (a project folder like any other, with the gallery images and the cover as JPEG to keep the app light). On the home screen, "Explore the sample story" appears while it is not in the library: `SampleProjectInstaller` copies the files to the projects folder (into a `.partial` folder that only becomes the final one when it finishes), the library is reloaded and the project opens. After that it is an ordinary project that can be edited or deleted; if it is deleted, the action comes back. Installing again without deleting copies nothing. New files of the sample must be declared in `pubspec.yaml`, folder by folder.

## Web demo

The app also builds for the web (`flutter build web`), as a demo the website links to. A browser has no folders, so every repository reads and writes through `fs`, in `packages/plotcraft_core/lib/core/file_system.dart`: the real disk on the desktop, a `MemoryFileSystem` (from `package:file`) in the browser, chosen in `main`. Code that needs a file uses `fs.file(path)` and `fs.directory(path)` instead of `File(path)` and `Directory(path)`. In the browser the app starts from the bundled sample story, so what is written is gone when the page closes. The things that only exist on the desktop (the window, the system spell checker, system fonts, the MCP bridge, watching the folder) are switched off there, and `isMacOS`/`isLinux`/`isWindows` in `lib/core/platform/platform_support.dart` replace `Platform`, which throws on the web. The `Website` workflow builds the demo and publishes it at `/demo/` beside the site.

## Persistence

Each project is a local folder with a manifest and materials. Preferences only store the library paths, the default location for new projects, the theme and the font. `easy_localization` persists the language. With no previous preferences, the initial language is English and the theme is Gris Night. The on-disk format is described in [Project model](project-model.md).

## Extension

To add a translation, create `assets/translations/<code>.json` following the same keys as `en.json`. The language list is built from the bundled translation files.

To add a theme, create a JSON in `assets/themes/` following the contract described in [Experience and preferences](experience-and-preferences.md). Default themes remain declared in code; themes from assets are loaded together with them and appear in the same selection.

## Current limits

The desktop home area lets you create, find, sort, open and delete projects, and configure language, theme, font and base folder on their own pages. An open project is a workspace in panels: activity bar, side panel with chapters or elements, tab area (overview, project settings, gallery, story map, timeline, reading mode, and chapters and elements open at the same time) and inspector, all resizable, with widths saved locally. The editor is rich text (`flutter_quill`) for the single manuscript or for chapters, with the system spell checker, element mentions (`@` or automatic detection of names), gallery images and project fonts. The book index and the elements are persisted in their own files inside the project folder; the workspace coordinates those rules through `ProjectWorkspaceStore`.
